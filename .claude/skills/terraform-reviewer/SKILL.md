# Terraform Expert Reviewer

Reviews Terraform code generated by the terraform-from-diagram skill against:
1. Project specifications (review gate files in agent/review/)
2. AWS best practices and Terraform standards
3. Security and compliance rules
4. IAM least-privilege requirements
5. The confirmed build plan and dependency wiring

---

## Activation Requirement

**Minimum prerequisite:** Gate 2 confirmed AND `terraform/` directory scaffolded.

Check `.claude/memory/tf-state.json`:
- `gate2_build_plan: "CONFIRMED"` AND `scaffold_complete: true`

If not met:
```
❌ Nothing to review yet.
   /tf-review requires at least Gate 2 confirmed and terraform/ scaffolded.
   Run /ServiceModelerConfirm first.
```

If scaffold done but no modules built yet:
```
⚠️  terraform/ is scaffolded but no modules built yet.
    Review will cover: structure, boilerplate files, wiring stubs, iam-github-oidc/
    Run /ServiceBuilder to generate modules, then re-review for full coverage.
```

---

## Review Scope

| Command | What it reviews |
|---------|----------------|
| `/tf-review` | All built modules + environments/ + iam-github-oidc/ |
| `/tf-review {service-name}` | One specific module only |
| `/tf-review wave:2` | All built modules in wave 2 |
| `/tf-review structure` | terraform/ directory structure and boilerplate only |
| `/tf-review iam` | IAM roles, policies and resource-based policies only |
| `/tf-review security` | Security-focused review only |
| `/tf-review plan` | Review all spec files in agent/review/ (no code needed) |

## Review Categories

Read `references/review-checklist.md` for the full checklist per category.

### Category 1 — Structure & Standards

- Module file structure (main.tf, variables.tf, outputs.tf, versions.tf, tests/)
- `required_version` only in root module, not in child modules
- `required_providers` present in every module
- `locals` used for all name construction (never inline string interpolation in resources)
- Consistent naming: `snake_case` for vars/resources/outputs, `kebab-case` for module dirs
- Resource naming follows `${var.project_name}-${var.environment}-{service}` pattern
- Every taggable resource has `tags = local.common_tags`
- `ManagedBy = "terraform"`, `Project`, `Environment`, `Module` tags present

### Category 2 — Variables & Outputs

- Every variable has `description` and `type`
- Sensitive variables have `sensitive = true`
- No defaults on required config (VPC IDs, passwords)
- Validation blocks on string variables with known valid values
- Outputs export `id`, `arn`, `name` at minimum
- Sensitive outputs have `sensitive = true`

### Category 3 — Security

- No `0.0.0.0/0` ingress on security groups without a comment
- S3 buckets have `aws_s3_bucket_public_access_block` with all `true`
- RDS has `deletion_protection = true` in prod modules
- RDS has `skip_final_snapshot = false` in prod
- KMS encryption on RDS, S3, SQS, SNS where supported
- No secrets or real values hardcoded in `.tf` files
- Lambda has `reserved_concurrent_executions` set
- Lambda has CloudWatch log group with `retention_in_days`
- Lambda has `tracing_config { mode = "Active" }`
- ECS tasks have both execution role AND task role

### Category 4 — IAM Least Privilege

Cross-check against `agent/review/iam-model-review.md`:
- No inline policy uses `"Resource": "*"` for data services (S3, DynamoDB, SQS, SM)
- All resource ARNs are scoped to specific resources, not wildcards
- No role has `AdministratorAccess` or `PowerUserAccess`
- `aws_iam_policy_document` data source used (never raw JSON strings)
- Trust policies use exact service principals
- Cross-service permissions match what's in iam-model-review.md

### Category 5 — Dependency Wiring

Cross-check against `agent/review/build-plan-review.md`:
- All outputs listed in the dependency map are actually exported
- All variables receiving cross-module values are declared
- Root module `environments/dev/main.tf` wires modules correctly
- No hardcoded ARNs, IDs, or endpoints — all use `module.{name}.{output}`

### Category 6 — Testing

- Every module has `tests/main.tftest.hcl`
- Tests use `mock_provider "aws"` (no real credentials needed)
- Minimum 3 test cases: valid inputs, invalid environment, tags applied
- `tests/fixtures/test.tfvars` present with sensible values

### Category 7 — Spec Compliance

Cross-check against agent/review/ files:
- Module names match `services-review.md` Final Name column
- Wave dependencies match `build-plan-review.md`
- Config values match `build-plan-inputs-wave-*.md` (instance classes, sizes, etc.)
- IAM roles match `iam-model-review.md`
